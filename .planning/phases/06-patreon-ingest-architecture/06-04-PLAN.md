<objective>
Move download and parse work off the MCP request path into an explicit `sync` ingest job, leaving queries to read only the local catalog and manifest.

Purpose: `mode: 'deep'` is the default for `get_patreon_patterns` and can trigger up to 5 post downloads inside one tool call, each with a 120-second timeout — worst case, minutes of blocking inside an MCP request that most clients will have abandoned long before. Downloading is ingest work, not query work.
Output: A `sync` command (and reusable orchestrator) that owns all network and disk mutation, and a query path that is pure local read.
</objective>

  <name>Task 1: Build the sync orchestrator</name>
  <files>src/sources/premium/patreon-sync.ts, src/sources/premium/__tests__/patreon-sync.test.ts</files>
  <action>Create `runSync(opts: { full?: boolean; creators?: string[]; dryRun?: boolean; onProgress?: (e: SyncEvent) => void })` running four stages in order:

  1. **Catalog** — `refreshChannelCatalog` per configured creator (06-01).
  2. **Discover** — collect `patreon.com/posts/` URLs from the refreshed catalog's video descriptions, deduplicated by post ID.
  3. **Download** — for each post not already in the manifest (`hasPost`, 06-03), download it via the library downloader (06-02), bounded by `p-limit` at `PATREON_SYNC_CONCURRENCY` (default 3). Respect the typed failure reasons: `cookie-expired` aborts the whole stage immediately (every subsequent download would fail identically), `not-entitled` and `not-found` skip that post and continue, `network` retries once with backoff.
  4. **Reindex** — `reindexPost` per successful download, then a final `reindexAll` to prune deleted directories.

  Emit `SyncEvent`s for stage start/finish and per-post outcomes. Return `{ catalogVideos, postsDiscovered, postsDownloaded, postsSkipped, failures: Array<{ url, reason }>, quotaUsed, durationMs }`. Under `dryRun`, run stages 1-2 and report what stage 3 would do without downloading. Resumability falls out of the `hasPost` check — assert it explicitly with a test that interrupts and re-runs.</action>

  <done>A mocked sync downloads only unindexed posts, aborts the download stage on `cookie-expired`, continues past `not-entitled`, and a re-run after interruption downloads nothing already indexed.</done>
