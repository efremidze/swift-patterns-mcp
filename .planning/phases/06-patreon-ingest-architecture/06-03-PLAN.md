<objective>
Replace the recursive filesystem scan with a persisted content manifest, so downloaded Patreon content is parsed once at ingest rather than re-walked and re-unzipped every 30 seconds.

Purpose: `scanDownloadedContent()` walks the whole content tree, reads every `.swift` and `.md` file, and re-extracts every zip into memory behind a 30-second TTL cache. Every 30 seconds, all archives decompress again. Cost grows linearly with the user's library and never plateaus, the full text of every downloaded file stays resident in the cached `DownloadedPost[]`, and `isPostDownloaded()` triggers a full tree walk to answer a single-key question.
Output: A manifest-backed index with incremental, mtime-driven refresh and metadata-only residency.
</objective>

<task type="auto">
  <name>Task 1: Define and build the manifest</name>
  <files>src/sources/premium/patreon-index.ts, src/sources/premium/__tests__/patreon-index.test.ts</files>
  <action>Create `patreon-index.ts` persisting a manifest at `getSwiftMcpDir()/patreon-index.json`:

  ```
  { version: 1, updatedAt: string, posts: Record<postId, {
      postId, dirName, title, publishDate, creator,
      fingerprint: { maxChildMtimeMs, fileCount, totalBytes },
      excerpt: string,          // <= PATREON_EXCERPT_LENGTH chars, the ranking corpus
      files: Array<{ filename, filepath, type, sizeBytes, extractedFrom?: string }>
  }> }
  ```

  Two things the schema must carry explicitly:

  - **`excerpt`** is the ranking corpus Task 2 ranks on. It has to be persisted, not recomputed: without it a restart either loses ranking fidelity or forces a full re-read of every file. Bound it at `PATREON_EXCERPT_LENGTH` and refresh it whenever the post's fingerprint changes.
  - **`fingerprint` replaces a bare directory mtime.** Editing a `post.json`, a Markdown file, or a zip *inside* a post directory does not update the parent directory's mtime on ext4 or APFS — only adding or removing an entry does. A dir-mtime-only check would therefore serve stale metadata and stale excerpts indefinitely. Compare the max child mtime, the file count, and the total byte size together; any change re-parses that post.

  `files[]` carries no `content` — full content is read on demand. Note that `excerpt` **is** patron content, so the manifest is not metadata-only: write it with `{ mode: 0o600 }` and chmod an existing manifest on write, exactly as 06-02 does for the session cookie. Export:
  - `loadManifest()` / `saveManifest()` with atomic write (temp + rename) and recovery from a corrupt or version-mismatched file by rebuilding from scratch.
  - `reindexAll(opts?)` — walk the content tree once, and for each post directory compare `dirMtimeMs` against the manifest; only re-parse changed or new directories. Extract zips here and record each contained Swift/Markdown file as a `files[]` entry with its `zipEntry` path.
  - `reindexPost(postPath, creator)` — index a single post directory and upsert it.
  - `getPost(postId)` / `hasPost(postId)` — O(1) lookups honouring the existing directory-name matching rules (`<id>`, `<id> - Title`, `<id>-Title`) via a prebuilt alias map.
  - `readFileContent(entry)` — read a manifest file entry's content directly from disk. **Zip contents are materialized during reindex, not read through at query time**: extract each archive's Swift/Markdown entries once into a sibling `.extracted/` directory under the post and point `filepath` at the extracted file, recording the archive in `extractedFrom` for provenance. Reading through to the archive on demand would reopen and decompress it on every query that touches the post, which is the cost this plan exists to remove. Delete a post's `.extracted/` directory when its fingerprint changes, before re-extracting.

  Preserve the current metadata precedence (`post_info/post-api.json` then `post.json`, falling back to the directory name) and the current skip list (`node_modules`, `.git`, `__MACOSX`, `.patreon-dl`, `post_info`, `campaign_info`).</action>
  <verify>npm test -- src/sources/premium/__tests__/patreon-index.test.ts</verify>
  <done>A fixture tree indexes correctly; a second `reindexAll` re-parses nothing when nothing changed; editing a file *inside* a post directory without touching the directory itself still triggers a re-parse of only that post; zip entries are materialized once and not re-extracted on a subsequent unchanged reindex; and a corrupt manifest rebuilds without throwing.</done>
